Registration contract (init input per task): {id, ref, owner, scope:'development'|'experiment', experimentSha?, evidence?}
  - gate ON + scope missing/unknown  => task BLOCKED (scope_missing/scope_unknown). Old tasks without scope must be re-registered
    with an explicit scope; this is deliberate so a new experiment cannot become "development" by omitting a field.
  - experiment needs all 6 evidence items (see REQUIRED in the module): status exactly 'PASS', sha == experimentSha, evidence id.
  - Who writes the evidence: only the owner-approved registration path. A runtime that supplies evidence (reviewer result store,
    operations confirmation record) does not exist yet => UNPROVEN / BLOCKED. Evidence update after init (withdraw/refresh) also has no
    approved write path yet; today it means a new owner-approved registration.
Limits (unproven): no live run; gate does not prove operations settings, does not replace approval/budget/trusted Codex verdict;
  a task already RUNNING is not stopped by withdrawal (only unsent outbox entries are); BLOCKED tasks need an explicit owner re-registration (no resume policy).
Recovery: leave QUEUE_SECURITY_GATE unset (gate OFF) or revert the commit; state branch is kept, nothing is deleted.
