## 2. 영상 확인 → 만남 관문 계약(대표 §10) — DESIGN 계약 · 구현 0

세 기록은 서로 다르다: **통화 참여**(V1) ≠ **모습 확인**(V2) ≠ **만날 의사**(V3).

- V1 `video_session`: `{ id, match_id, provider_room_id, created_at, ended_at }` + `video_participation(session_id, user_id, joined_at, left_at, camera_on_seconds)` — 공급자 서버 콜백(서명 검증)만 기록. 화면이 보낸 「참여함」은 믿지 않음.
- V2 `appearance_check(match_id, user_id, session_id, checked_at)` — 그 연결의 그 세션에 **둘 다 참여**하고 **카메라 켠 시간 > 0** 일 때만 각자 누를 수 있음.
- V3 `meet_intent(match_id, user_id, intent: yes|not_now|no, at)` — 각자. 상대에게는 「둘 다 yes」일 때만 결과를 알림(한쪽 의사 노출 0).
- V4 약속 조율(`meet_plan`) 허용 조건(서버가 모두 확인):
  같은 유효 연결(status approved · 차단·종료·안전 제한 없음) + 참가자 본인 + 마지막 확인 구간 + 유효 공개·동의·자산 판 + 그 연결의 영상 세션에 양쪽 참여(V1) + A·B 각각 V2 + A·B 각각 V3=yes.
- 우회 금지: 카메라 OFF · 연결 실패 · 다른 방(다른 match_id) 세션 · 위조 콜백(서명 불일치) · 오래된 동의(consent_version 불일치) · 철회 뒤.
- 영상 확인을 신원·안전 보증 배지로 쓰지 않는다(「확인된 사람」「안전한 상대」 문구 0).
- 만남 전 안전 안내: 「약속했어요」 뒤 + 이야기 화면(접어 둔 안내)에서 이미 접근 가능(이번 PR). V4 화면에도 같은 목록을 둔다.
- 승인 필요: 미디어 공급자 선택 · Secret · 개인정보 처리(영상 메타데이터 보관 기간) · DB/RLS(위 4표).
- 검사(구현 시): 카메라 OFF 로 V2 거부 · 다른 match 세션 id 로 V2 거부 · 서명 틀린 콜백 무시 · 한쪽만 V3=yes 면 V4 403 · 차단 뒤 V4 403 · 동의 판 바뀌면 V4 403.

## 3. 72시간 — 응답 대기 정책표(대표 §12 · 설계안 · 실사용자 활성화 0)
