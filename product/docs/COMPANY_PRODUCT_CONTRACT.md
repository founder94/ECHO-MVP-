# DO IT COMPANY · 제품 기준

2026-09-21 한국시간. 대표의 이 대화에서 확인된 요구와 구현 기준을 보관한다. 실제 임원 회의나 법률 검토를 거쳤다는 기록이 아니다.

## 우리가 만드는 경험

호기심을 만드는 브랜드 홈페이지에서 시작해, 사용자가 원하는 관계를 고르고 자신의 이야기와 사진을 준비한다. AI는 사용자의 말을 정리해 제안한다. 그 설명이 맞는지는 사용자가 정한다. 서버는 사용자가 확인하거나 고친 내용을 기억하고 다음 대화에 반영한다.

AI가 사람을 단정하는 서비스로 만들지 않는다. 사진·정정·서버 저장이 작동하지 않으면 디자인이 좋아도 핵심 완료가 아니다.

## 디자인 정본

- 기존 우주 사진 9장, 검정 배경, 흰 글자, 기존 글씨체, 대표 제공 공식 D 심볼을 유지한다.
- 실버는 버튼·얇은 하이라이트·표면 깊이에 절제해서 쓴다. 서브 문장과 시작 버튼은 읽기 편하게 조금 두껍게 한다.
- 스크롤 장면은 갑자기 잘리거나 경계선이 나타나지 않도록 이어진다. 동작 감소 설정도 존중한다.
- 진행률을 보여주는 불필요한 도입 화면과 반복 STEP 소개를 넣지 않는다.
- 문장은 사람에게 말하듯 짧고 구체적으로 쓴다. 내부 개발 용어·가짜 완료·가짜 수치를 사용자 흐름에 넣지 않는다.

## 사용자 흐름

1. 브랜드 소개 → 시작하기 한 번 → 목적 선택 또는 기존 진행 복원.
2. 목적은 운영 DB의 활성 목록을 정본으로 쓴다. 과거 12개 목록을 되살리지 않는다.
3. 로그인 후 대화부터 시작하거나 소개·사진을 먼저 준비할 수 있다. 기존 완성 프로필을 초기화하지 않는다.
4. 사진은 6개 슬롯에 한 장씩 추가·교체하고 대표 사진을 고른다. 카메라와 앨범을 함께 제공한다.
5. 최근 2개월 안에 찍은 본인 사진만 쓰도록 안내한다. 촬영 메타데이터가 범위를 벗어나면 차단한다. 정보가 없으면 본인 확인 체크를 받는다. 메타데이터는 수정 가능하므로 촬영 시점 검증·본인 인증 완료로 표시하지 않는다.
6. 내 대화와 확인한 이해는 개인 기록이다. 프로필이나 다른 사용자에게 자동 공개하지 않는다.

## AI와 서버의 책임

- 버튼은 `맞아요 / 조금 달라요 / 그게 아니에요 / 직접 설명할게요` 네 가지다.
- LLM은 후보를 만든다. 서버가 소유자·버전·상태·중복 요청을 검사하고 저장 여부를 결정한다.
- 사용자 원문과 AI 제안, 확인, 정정, 거절, 직접 설명을 구분한다. 원문 공백과 줄바꿈도 보존한다.
- 현재 이야기의 정정·직접 설명이 과거 AI 확인보다 우선한다. 거절한 의미를 다음 질문의 전제로 되살리지 않는다.
- 다음 질문은 저장된 정본을 읽어 생성한다. 질문 배열이나 가짜 응답으로 성공을 꾸미지 않는다.
- 관계 목적도 서버 DB에서 읽지만, 선택 목적만으로 성격을 추론하지 않는다.
- 정정·목적이 생성 도중 바뀌면 옛 맥락의 AI 결과를 저장하지 않는다.
- 새로고침·화면 이동만으로 AI를 다시 호출하지 않는다. 같은 요청의 성공 응답을 복원한다.
- 사주·타로는 별도 선택형 재미 콘텐츠이며 성향 사실·관계 적합도·본인 확인 근거로 쓰지 않는다. 기존 B 전체 여정을 필수로 되살리지 않는다.

## 완료 판정과 승인 경계

화면을 게시한 것과 핵심 서버를 공개한 것은 별도 상태다. 새 DB/Edge 변경은 과거 대표가 정한 별도 승인 범위를 따른다. 변경 SQL·검사·복구안을 먼저 준비하고 구체 범위를 보고한다. 승인되지 않은 서버 기능은 화면 스위치를 켜서 작동하는 것처럼 보이게 하지 않는다.

전체 서비스 완료에는 실계정의 저장→재로그인→사진 복원, 네 가지 반응→다음 실제 AI 대화 반영, 정책·동의, 삭제·탈퇴, 사람 연결의 실제 동작까지 증거가 필요하다. 이번에 준비하지 않은 기능은 준비 중으로 남기며 전체 완료율을 임의로 계산하지 않는다.
