# ECHO Failure Taxonomy (v1 · 2026-09-25)

모든 실패는 **Failure Type**(무엇이 잘못 보였나) 하나 이상과 **원인 Layer**(어디서 생겼나) 하나 이상으로 분류한다.
실패 하나마다 정규식 하나를 더하는 식으로 고치지 않는다. 먼저 Layer 를 가른다.

## 1. 원인 Layer

| Layer | 뜻 | 이 층에서 고치는 방법 | 대표 사례 |
|---|---|---|---|
| Context | 모델이 받은 입력에 필요한 것이 없거나, 없어야 할 것이 있었다 | 입력 구성(최근 대화 · 정정 · 거절 · 답한 의도 · 목적). 남은 수·주제 순서 제거 | GF-04, GF-19 |
| Orchestration | 서버가 모델 후보를 잘못 막거나 잘못 통과시켰다. 규칙이 모델보다 먼저 잘못 결정했다 | 서버는 저장·정정·거절·의도·안전·상태만 결정. 문자열 품질 검사 금지 | GF-01~03, 05~08, 10~12, 14, 18 |
| Product Contract | 제품 규칙 자체가 기준본과 다르다 | 대표 결정 → 계약 수정 | GF-09 |
| Model | 같은 좋은 입력을 줘도 모델이 틀린다 | 같은 B 구조로 모델 비교(GPT/Claude/Gemini) — 대표 승인 뒤 | **아직 분리된 사례 0** |
| Infrastructure | 배포·네트워크·지연·자동 재요청·환경 | 배포 과정 · 지문 대조 · 시간 상한 | GF-11, GF-13(배포 누락), GF-20 |
| Evaluation | 검사가 실제 실패를 잡지 못하거나 통과로 셌다 | 실제 문장 재생 · 실AI Replay · 검사 역검사 | GF-15, GF-16, GF-17 |

- Model Layer 는 Context·Orchestration 을 먼저 정리한 뒤에만 판정한다.
  - 운영 A 의 실패는 입력(GF-04)과 서버 검사(GF-01·02)가 이미 불리한 상태에서 났다. 그래서 모델 탓으로 분리되지 않는다.

## 2. Failure Type

| Type | 대표 원래 표현 | 관측 방법 |
|---|---|---|
| 방향이탈 | 앞뒤가 안 맞다, 갑자기 | 방금 말과 상관없는 주제로 이동(블라인드 검수) |
| 반복설명 강요 | 몇 번째 같은 말이야 | 사용자가 「이미 말했다」 계열 항의 |
| 질문의도 반복 | 같은 걸 또 묻는다 | 같은 뜻 질문 재등장(의도 장부 · 블라인드) |
| 정정무시 | 그게 아니라고 | 정정 뒤 고치기 전 해석 재사용 |
| 거절 의미 재등장 | 아니라고 한 걸 또 | 거절한 해석·질문 방향이 다른 표현으로 다시 나옴 |
| 미확정 사실화 | 내가 언제 그랬어 | 사용자가 확인하지 않은 추측을 사실처럼 말함 |
| Context 유실 | 방금 말했잖아 | 저장 안 한 말·직전 턴을 모름 |
| Context 오염 | — | 옛 회차·다른 목적 정보가 섞임 |
| Repair 실패 | 문제제기 뒤에도 그대로 | 항의 뒤 인정·방향 전환 없음, 또는 멈춤 |
| 오분류 | — | 답/되묻기/항의/정정/모르겠어요를 잘못 가름 |
| 과잉 Guard | 다음 질문을 못 만들었어요 | 서버가 정상 후보를 전부 탈락 |
| 문장 파손 | 오타 같다 | 끼워 넣은 말 때문에 문장이 깨짐 |
| 무거운 질문 | 딥하다 | 추상·상담형 질문 |
| 지연 | 느리다 | 턴 시간(p50/p95) |
| Mock PASS / 실AI FAIL | 검사는 통과했다며 | 배포 전 가짜 검사 통과, 실제 첫 입력 실패 |
| 검사 결함 | — | 검사가 이름과 다른 것을 확인, 입력을 못 읽음 |
| 배포 불일치 | — | 운영 파일 ≠ 검사한 파일 |

## 3. 상태(Lifecycle)

```
OBSERVED → REPRODUCED → ISOLATED(원인 Layer 분리) → EXPERIMENTED(해결 실험)
        → REVERSE-CHECKED(정상 사례 역검사 · 해결 장치 일부러 망가뜨려 검사가 잡는지)
        → REAL-AI-VERIFIED(실제 AI Replay 통과) = VERIFIED
```

| 상태 | 뜻 |
|---|---|
| UNRESOLVED | 원인은 알았거나 모르지만 운영에서 해결되지 않았다 |
| MITIGATED | 운영에서 완화 조치를 했다. 실AI 재검증·정상 사례 역검사를 다 거치지 않았다 |
| RESOLVED | 검사 도구·배포 과정처럼 AI 품질이 아닌 결함을 고치고 확인했다 |
| VERIFIED | 위 lifecycle 끝까지 통과한 해결책이 있는 실패(현재 0) |
| FAILED_SOLUTION | 시도했으나 새 실패를 낳거나 효과가 없던 해결책 → `FAILED_SOLUTIONS_ARCHIVE.md`, 지우지 않는다 |

## 4. 출처 표시
- **ACTUAL**: 운영 기록 또는 대표 실기기 입력. 근거 문서 경로를 반드시 적는다.
- **ACTUAL(캡처 재구성)**: 대표 화면 캡처에서 옮김. 원문 일부가 빠졌을 수 있다.
- **SYNTHETIC**: 예문·대체 입력. 실제 사용자 입력이 아니다.
- **코드 확인**: 사용자 사례 없이 코드로 확인한 결함.
- 결과 표시: **[MOCK]** 가짜 AI · **[REPLAY]** 실제 문장을 서버 코드에 재생(AI 호출 0) · **[REAL]** 실제 AI.
  - [MOCK] 통과는 [REAL] 통과가 아니다.
