# ECHO "친구 같은 AI" 3차 수정 보고 — 실사용 캡처 9장 원인·수정·검증 (2026-09-16, 회사모드)

단계 표기: **코드 수정 완료 → 로컬 검사 완료(QA 60/60, tsc·lint 0) → 서버 함수 배포 완료(echo-journey v12 · get-step-question v21, 바이트 대조) → 운영 실기기 확인 NOT RUN.** 대표가 실기기로 같은 장면을 다시 해보기 전까지 "운영 확인 완료"라고 쓰지 않는다.

## 1. 현재 상태(캡처·DB·로그로 확인한 사실)
대표 아이폰 캡처 9장(do-it.company 실사용)에서 본 증상 4가지:
| # | 증상 | 확인한 증거 |
|---|---|---|
| A | AI 가 내 질문에 답하지 않고 되묻기만 함("어떻게 대처하는게 좋을까?", "ai가 오타기 날수도 있어?", "질문했는데 답을 못햐?") | 서버 코드에 '사용자가 물었을 때' 분기 자체가 없었음. 사용자 문장은 항상 '답변' 또는 '질문 피드백'으로만 분류 |
| B | 공감 문장이 내 말을 그대로 따라 씀(되받아치기) | 프롬프트가 "acknowledgement 에 anchor 를 글자 그대로 넣어라"고 요구하고 anchor 길이 제한이 없어 문장 전체를 anchor 로 복사 → 서버 규칙(ack_anchor)이 그 복사를 '통과'시킴 |
| C | STEP 4 "잠시 연결이 원활하지 않아요. 질문을 만들지 못했어요" | 운영 로그 `[ej] candidates_blocked step=4 mode=feedback parsed=3 attempt=1/2` → `[ej] no_candidate step=4 mode=feedback blocked_total=6` **2회(2026-09-16 20:03:25~20:03:39 UTC)**. OpenAI 오류·HTTP 오류 0건 → 연결 문제가 아니라 **서버가 후보 6개를 전부 차단**한 것 |
| D | 버퍼링이 느림 | 후보가 차단될 때마다 OpenAI 를 다시 부름(1회 최대 6초). C 처럼 2회 다 막히면 12초+ 뒤에 실패 화면 |

원인(코드 근거):
1. **행동 분기(Action Router) 부재** — A. 사용자 물음을 답할 대상으로 보지 않았다.
2. **"답을 못햐?" 가 '부담 피드백'으로 분류** — `question-quality.ts` BURDEN 규칙 `/(답|대답|말).{0,10}(못|어렵|힘들)/` 에 걸려 mode=feedback(고정 문장 "제가 어렵게 물었어요…")으로 진행. 질문에 대한 답은 없음.
3. **의도 반복 검사가 대화 전체와 비교** — `repeatsQuestionIntent(c.question, block.asked)` 가 STEP 1 부터 물은 모든 질문과 비교. 의도 태그 12종이 STEP 4 쯤 소진 → 새 후보가 전부 `repeat_intent` 로 차단 → C.
4. **시도 2회, 완화 없음** — 두 번 다 막히면 바로 실패.
5. **anchor 길이 무제한 + ack 에 anchor 포함 강제** — B.
6. **세션 간 기억 없음** — 다음 여정에서 지난 여정 내용을 전혀 참고하지 않음(대표 요구: "내 데이터를 또 접속하면 결제 후 계속 이어질 수 있게").

## 2. 수정(서버 2개 함수, 프론트 변경 없음)
| 규칙 | echo-journey(STEP 3~7) | get-step-question(STEP 1~2·이해·후속) |
|---|---|---|
| **asked 모드(먼저 답하기)** | `isUserQuestion(직전 여정 답변)` 이면 피드백보다 우선해 asked. 후보에 `reply`(1~2문장, 물음표·금지어 금지, 160자) 필드 요구. 서버가 검사해 부적합하면 고정 문장 "제가 대신 정답을 정해 줄 수는 없지만, 같이 찾아볼게요." 사용. 화면 = reply + 빈 줄 + 질문 1개 | 후속 질문 동일(`followupMode` asked → feedback → normal). 이해 요약(understanding)도 사용자가 물었으면 1문장 먼저 답한 뒤 요약 |
| **되받아치기 방지** | anchor "2~12자 핵심 표현(문장 전체 복사 금지)" + `isParrot`(사용자 문장 포함 또는 겹침 0.8 초과) 이면 공감 문장 버리고 질문만 | 동일 |
| **의도 반복 범위** | 최근 여정 질문 2개와만 비교 | 최근 질문 2개와만 비교(`INTENT_HISTORY = 2`) |
| **시도 3회, 마지막은 완화** | `ATTEMPTS: 3`. 3번째는 `relaxed` — 의도 반복·중심표현 재사용만 풀고 금지어·근거·거절·글자 반복 규칙은 유지 | `GENERATION_ATTEMPTS: 3`, 3번째 relaxed(의도 반복만 완화) |
| **공감 문장 검사** | normal 외 모드(asked 포함)는 공감 문장을 화면에 안 쓰므로 비우고 검사(공감 문장 규칙으로 후보를 잃지 않음) | 동일 |
| **지난 여정 기억(Context Memory)** | ask 시 `reports.summary`(같은 사용자의 가장 최근 다른 대화 리포트 요약, 300자) 를 프롬프트에 "사실 근거 아님·같은 주제면 이어서 반영"으로 전달 | STEP 1·2·이해·후속 모두 동일 |
| **진단 로그** | `[ej] candidates_blocked … relaxed= reasons=사유:수` 추가 | `[gsq] candidates_blocked/candidates_schema_fail/no_candidate` 추가 |

프롬프트에도 사용자 물음 노트("먼저 답할 것 … 정답을 대신 정하지 않고, 의료·법률·재무 조언 없이, ECHO 자체를 물었으면 사실대로 인정")를 넣었다. 하드코딩 질문 없음. 결제·DB·RLS·라우터 변경 없음.

## 3. 세션 간 기억 — 지금 되는 것 / 안 되는 것(사실)
- 되는 것: 결제 후 리포트가 생긴 사용자가 **다음 여정**을 시작하면 STEP 1 부터 지난 리포트 요약을 참고한다(새 테이블 없이 기존 `reports` 만 사용). 결제한 리포트는 보관함·재열람 유지(기존).
- 안 되는 것(STOP 게이트): 리포트 없이 끝난 무료 여정의 기억, 여러 여정을 합친 장기 기억. 이건 새 테이블(사용자별 기억 요약)이 필요하므로 대표 승인 후 `supabase/drafts/PENDING_*.sql` 초안 → 스테이징 순서로만 가능.

## 5. 대표가 실기기로 확인할 것(이 3가지가 되면 "운영 확인 완료")
1. STEP 3~7 중 아무 때나 "어떻게 하는 게 좋을까?" 라고 써 본다 → 첫 줄에 **짧은 답**이 먼저 오고, 그 다음 줄에 질문 하나가 온다.
2. "ai가 오타 날 수도 있어?" 처럼 ECHO 자체를 물어본다 → 사실대로 인정하는 답 + 질문.
3. STEP 4 이후에도 "질문을 만들지 못했어요" 가 연속으로 나오지 않는다(나오면 시각을 알려주면 로그의 `reasons=` 로 원인을 바로 본다).
