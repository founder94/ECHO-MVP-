# ECHO AI 질문 맥락 P0 — 원인·수정·검사 (v14.4 · 2026-09-24)

근거: 대표 긴급 정정 "AI 질문 자체가 앞뒤 대화와 맞지 않는다 … 목표 = 대화의 논리적 연결성".
상태: **로컬 수정·검사 완료, 운영 미배포**(서버 doit-understanding 운영은 버전 23 = v14.3 그대로). 배포는 대표 승인 전 STOP.

## 1. 앞뒤 안 맞는 질문의 실제 원인 (코드로 확인)
1. **짧은 답(12자 이하)이면 서버가 새 주제로 넘기고, 그 지침이 "앞 말과 억지로 잇지 않아도 된다"였다.** (`pickStrategy`, `generateInsights` 구제, `STRATEGY_GUIDE.CHANGE_DIRECTION`)
2. **새 주제로 넘길 때는 "직전 말과 이어지는가" 검사를 건너뛰었다.** 판정이 불허해도 첫 줄(받아 주는 말)만 떼고 질문을 그대로 보냈다. (`composeFollowup`: `if (!newBranch && !connected)`, `if (newBranch) question = askedQ`)
3. **AI 가 실패하거나 질문이 버려지면 고정 질문으로 건너뛰었다.** "알겠어요. 어떤 사람한테 끌려요?" 같은 주제별 고정 문장(`fixedDirectionQuestion`·`EASY_QUESTION`)과 "어떤 사람이면 편하게 느껴지세요?"(`GENERIC_RESCUE`)가 앞 답과 무관하게 나갔다. 긴 답에서 AI 가 딴 질문을 내면 서버가 그 질문은 막았지만, 대체 문장이 다시 딴 주제였다.
4. **AI 에 간 맥락이 모자랐다.** 이번 대화의 앞 질문·답 짝(history)은 주제 판정에만 쓰였고 질문 생성에는 가지 않았다. "직전 질문"은 "마지막으로 저장된 질문"이라서 ① 첫 답(화면 고정 질문)엔 비어 있었고 ② 되묻기로 바뀐 질문을 몰랐고 ③ 새로고침 뒤엔 이 답 "다음에" 물은 질문을 직전 질문으로 읽을 수 있었다.
5. **"근데 왜 이런 걸 물어봐?"를 답으로 저장했다.** AI 에게 하는 질문을 구분하지 않았다.

## 4. 무엇이 빠졌거나 잘못 연결됐나
- 빠짐: history(3), 정확한 직전 질문(1), "이어받는 구절" 검사(A·H).
- 잘못 연결: 새 갈래 = 연결 검사 면제, 판정 불허 = 첫 줄만 떼고 발송, AI 실패 = 딴 주제 고정 질문.
- 검증 기준 A~H 가 어디서 보장되는지(v14.4): A 직전 답 관련 = link+다리 검사(서버 규칙)+판정 / B 반복 = `repeatsAsked`+판정 / C 이미 답한 사실 = history 를 판정에 넘김(**LLM 판정만 — 규칙 검사 없음**) / D 거절 = 글자 겹침+의미 판정 / E 정정 우선 = confirmed 순서+superseded+판정 / F 말하지 않은 전제 = 판정(**LLM 만**) / G 목적·단계 = strategy·hints(프롬프트) / H 갑작스런 주제 전환 = link+다리+판정.

## 5. 수정 내용 (v14.4, 로컬)
1. 새 주제 지침을 "방금 답을 받아 준 뒤 그 답에서 이어 넘어간다"로 바꿈. "억지로 잇지 않아도" 삭제.
2. 모든 다음 질문(이어 묻기·구제)은 **link**(방금 답에서 그대로 인용)를 내야 하고, 서버가 원문에 있는지·첫 줄이나 질문이 그 말을 실제로 받는지 확인. 새 갈래는 첫 줄(다리)이 필수. 거절 직후는 예외(거절한 뜻을 되살리지 않도록 — 판정이 대신 본다).
3. 판정 기준 1순위를 "직전 질문 → 답 → 이 질문이 한 줄로 이어지는가"로. 불허면 첫 줄만 떼고 보내던 길 삭제.
4. history(최근 5개 질문·답 짝)와 정확한 직전 질문을 생성·판정 모두에 전달. 화면이 `answeredQuestion`(그 답을 적을 때 떠 있던 질문)을 보낸다. 없으면 답 시각으로 짝짓는다.
5. 주제별 고정 질문 목록(EASY_QUESTION)·일반 질문(GENERIC_RESCUE) 삭제. AI 실패 때는 새 주제로 건너뛰지 않고 방금 답에 머문다("…"라고 하셨죠. 조금만 더 들려줄래요? / 방금 한 말, 조금만 더 들려줄래요?).
6. AI 에게 하는 질문(`isAskingAi`)은 기록하지 않고, 서버가 확인된 사실 5개 안에서만 먼저 답한 뒤 같은 질문을 다시 건넨다. 첫 질문에서도 같다.
- DB·RLS·마이그레이션·모델·Secret 변경 0. 화면↔서버 새·옛 판 어느 조합도 멈추지 않음(새 필드는 없으면 무시).

## 9. 아직 남은 실패·위험
- C(이미 답한 사실 재질문)·F(말하지 않은 전제)는 **LLM 판정에만** 기대고 규칙 검사가 없다.
- link 는 글자 겹침으로만 확인한다 — 진짜 AI 가 글자만 맞추고 뜻은 엇나갈 수 있다(판정이 마지막 방어).
- AI 가 연달아 실패하면 "조금만 더 들려줄래요?"가 여러 번 나와 다섯 칸을 한 주제에 쓸 수 있다.
- 새로고침 뒤 첫 답의 질문은 서버 기록에 없어 history 에 "(알 수 없음)"으로 간다.
- 대화 품질의 진짜 판정은 실기기(진짜 AI) 전까지 **확인 불가**. 그래서 **비공개 베타 가능 아님**.
