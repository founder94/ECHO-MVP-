## 4. 유지한 HARD RULE (서버 결정적)

| 규칙 | 서버가 하는 일 |
|---|---|
| Original | 원문을 그대로 보존한다 |
| 저장 순서 | 분류가 끝난 뒤에만 답으로 저장한다 |
| State | 회차 · 다섯 칸 · 처음부터 시작하기 이후 기록만 센다 |
| Confirmed / Unconfirmed | 맞다고 한 말만 사실로 쓰고, 확인 안 된 AI 이해는 따로 둔다 |
| Correction | 첫 "아니야"는 AI 0번 · 떠 있던 AI 문장을 거절로 저장 · 다음 질문에서 정정 전 문장을 막는다 |
| Rejection | 기존 글자 검사 + AI 자기 신고 |
| Already Asked | 기존 글자 검사 + 직전 질문 대조 |
| 원문 출발 | 단서가 원문 안에 글자 그대로 있어야 한다 |
| Safety | 저장 금지 입력은 AI 전에 막는다. 금지어 · 출력 쪽도 막는다 |
| 형식 | 질문 하나 · 빈 질문 금지 · 200자 이내 |
| UI 안내문 | 사실로 쓰지 않는다 |
| Permission | 토큰 실검증 · 본인 기록만 |
| Audit | 관측 로그(원문 없음) |

- 결정적 규칙이 없는 것:
  - Purpose(목적 이탈): LLM 자기 신고 + 원문 출발 검사만 있다.
  - Outcome: 쌓이는 곳이 아직 없다(P4).
- 새 숫자: 다시 만들기 1번(대표 LOCK "정상 1 · 예외 2"), HOT 3턴(대표 지정 2~3), 출력 상한 768(기존 값). 글이 자연스러운지를 가르는 문턱은 새로 넣지 않았다.

## 14. 예상 위험

1. **질문 품질은 프롬프트·모델에 달렸다.** 서버는 딱딱하거나 긴 질문을 더 이상 글자 규칙으로 막지 않는다. 판정은 LEVEL 3 로만 할 수 있다.
2. **분류 오판.** 진짜 답을 문제제기로 읽으면 저장되지 않는다(빠져나갈 문: 「이 말은 답으로 남길게요」). 반대로 문제제기를 답으로 읽으면 칸이 찬다. 실AI 빈도는 확인 불가다.
3. **자동 재요청 제거.** 질문을 못 만들면 사용자가 「다음 질문 받기」를 한 번 눌러야 한다. LLM 중복 방지 지시와 "사용자가 재시도하지 않아도"라는 기준이 부딪치는 자리라, 서버 안의 1번 다시 만들기로 줄였다.
4. 목적 이탈을 결정적으로 막는 규칙이 없다.
5. **「소개팅」 금지어와 히어로 문구가 부딪친다.**
   - 기준 문서 v3 §1 과 결정 기록 2026-09-21 은 「화면에 데이팅·소개팅… 단어는 쓰지 않는다」이다. FINAL LOCK 히어로 문구는 「찾아다니는 소개팅이 아니라」이다.
   - 대표 최신 지시대로 넣었고, 검사도 이 한 줄(부정문)만 예외로 두었다.
   - 대표 확인이 필요하다: 금지어 규칙을 이 문장만큼 풀지, 문구를 바꿀지.
6. **옛 문장 한 곳이 남아 있다.** 이야기 09 구간 아래 「지금은 목적 선택과 프로필 준비까지. 사람 연결은 준비 중입니다.」는 이번 범위가 아니라 그대로 뒀다. 연결 v1 이 운영에 있으므로 사실과 어긋난다. 대표 결정 뒤 별건으로 처리한다.
