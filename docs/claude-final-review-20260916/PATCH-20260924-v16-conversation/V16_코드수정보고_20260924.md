## 3. 유지한 서버 필수 규칙 (LLM 판단만 믿지 않음)

| 규칙 | 서버가 하는 일 |
|---|---|
| 원문 보존 | `original_text` 를 그대로 저장한다 |
| 저장 순서 | 말의 종류를 가른 **뒤에만** 답으로 저장한다. 종류를 못 읽으면 저장 0, 502, 입력창의 글은 그대로 둔다 |
| 칸·회차 | answer·unsure·설명 붙은 correction 만 칸을 채운다. 다섯 칸이면 끝(`roundFinished`)이다. 「처음부터 시작하기」 이후 기록만 센다 |
| 정보 상태 | confirmed·corrected 만 사실로 넘긴다. 확인 안 된 AI 이해(candidate)는 `unconfirmed` 로 따로 넘긴다 |
| 최신 정정 | 설명 없는 「그게 아니에요」는 규칙이 가르고 LLM 은 0번 부른다. 떠 있던 AI 문장을 거절로 저장한다. 다음 답에서는 그 문장을 정정 전 문장(superseded)으로 막는다 |
| 거절 의미 | 기존 글자 검사(`blockedByOverlap`, 기존 값)와 LLM 자기 신고, 둘 다 본다 |
| 이미 물은 질문 | 기존 글자 검사(`repeatsAsked`, 기존 값)와 직전 질문을 대조한다(되묻기만 예외) |
| 방금 말에서 출발 | 질문의 단서(`interesting_clue`)가 기준 원문 **안에 글자 그대로** 있어야 한다. 불만·되묻기일 때 기준 원문은 직전 정상 답이다 |
| 안전 | 저장 금지 입력(연락처 등)은 AI 를 부르기 전에 막는다. 질문·반응·AI 답에서도 한 번 더 막는다. 금지어도 막는다 |
| 형식 | 빈 질문·200자 초과·줄바꿈을 막는다. 질문은 하나만(기존 `singleQuestion`) |
| 화면 안내문 | 화면 안내문을 질문이나 사실로 쓰지 않는다(`FIXED_LINE_KEYS`) |
| 인증·권한 | 기존과 같다(토큰 실검증, 본인 기록만) |

- **목적 이탈**: 결정적으로 막는 규칙은 없다. LLM 자기 신고(`off_purpose`)와 "원문에서 출발" 검사로만 막는다(12절 위험).
- **새 숫자**: 넣은 숫자는 둘뿐이다.
  - 다시 만들기 1번(대표 LOCK "정상 1 · 예외 2"): `V16_ATTEMPTS = 2`
  - 출력 상한: v15 와 같은 값 768
  - 글이 자연스러운지를 가르는 문턱값은 새로 넣지 않았다.

## 4. 새 turn 계약

```
화면 → { action:"turn", text?, originalText?, answeredQuestion?, recordId?, skip?, asAnswer?, correction?, pendingCorrection? }
서버 → 상태 읽기(이번 회차 원문·질문 짝·정정·거절·맞다고 한 말·확인 안 된 말·목적·이미 물은 질문)
     → OpenAI 1번 : { turn_type, correction_rest, interesting_clue, acknowledgement, next_question, reason, 자기 신고 4개 }
     → 서버 필수 검사 → (걸리면 이유를 붙여 1번만 다시)
     → answer·unsure·설명 붙은 correction : 저장 → 다음 질문 저장(기존 doit_begin/finish_followup)
       ask : 사실(ASK_FACTS) 안에서 답 · 저장 0 · 같은 질문
       meta·complaint · 두 번째 "아니야" : 저장 0 · 반응 + 직전 정상 답에서 새 질문(기존 followup_skip 기록 · 새로고침 복원)
       fatigue · 설명 없는 첫 "아니야" : 규칙이면 OpenAI 0번
화면 ← { kind, saved, record?, question?, reply?, pause?, finished?, again?, rejected?, questionError? }
```

- 질문을 고르는 순서(프롬프트): ① 이어짐 → ② 궁금함 → ③ 사람다움 → ④ 가벼움 → ⑤ 한 걸음 → ⑥ 새로 알게 되는 것. ⑥을 1순위로 두지 않는다.
- 프롬프트에서 뺀 것: 과장된 연애 문구, 「~시군요」 같은 틀 문장, 예시 질문. 예시 질문은 하나도 넣지 않았다.
- `reason` 은 사용자에게 보이지 않는다. 관측용이다.
- DB 변경은 0건이다. 기존 RPC 3개(`doit_apply_record_create`·`doit_begin_followup`·`doit_finish_followup`)와 기존 이벤트 종류(`followup_skip`·`followup_reject`)만 쓴다. 운영 함수 정의는 읽기만 해서 확인했다.
- **관측 로그(원문·질문 문장 없음)**: request_id · turn · turn_type · by(rule/ai/user/cache/duplicate) · saved · result · llm_calls · llm_ms[] · db_ms · validate_ms · retry_reason[] · total_ms.

## 12. 예상 위험

1. **질문 품질은 이제 프롬프트와 모델에 달렸다.**
   - 서버는 딱딱하거나 긴 질문을 글자 규칙으로 더 이상 막지 않는다. 막는 것은 형식·반복·거절·원문 출발·안전뿐이다.
   - 품질 판정은 대표님 LEVEL 3(A 자연스럽다 / B 조금 어색 / C 뜬금없다, 목표 C = 0)로만 할 수 있다.
2. **분류 오판**
   - AI 가 진짜 답을 불만·되묻기로 읽으면 저장되지 않는다.
   - 빠져나갈 문 「이 말은 답으로 남길게요」를 넣었지만, 사용자가 눌러야 한다.
   - 반대로 문제제기를 답으로 읽으면 칸이 찬다.
   - 두 방향 모두 실AI 에서의 빈도는 확인 불가다.
3. **목적 이탈**: 결정적 규칙이 없다(LLM 자기 신고 + 원문 출발 검사만 있음).
4. **단서 검사**: "원문 안에 글자 그대로"이므로, 오타나 띄어쓰기가 섞인 원문에서 AI 가 조금 바꿔 인용하면 1번 다시 만든다(띄어쓰기·기호는 무시). 호출 2번까지 들 수 있다.
5. **화면 시작 안내의 다섯 칸 목록**(「어떤 사람에게 끌리는지·같이 뭘 하고 싶은지…」)은 그대로 뒀다.
