## 12. Root Cause

- **확정**
  1. FAIL-B 의 시작은 서버 규칙 `/^[^\s?]{1,6}\?+$/`(index.ts:182, 앱 conversationRules.ts:39)가 짧은 답 「취미생활?」을 "뜻 모르겠다(meta)"로 **강제 분류**한 것이다. LLM 은 바꿀 수 없다. meta 지시는 "같은 질문을 쉽게 다시"라서 엉뚱한 되물음이 나왔다.
  2. 대표의 방향 제시(「어떤 취미가 있냐고 물어봐야지」)가 `ask` 로 분류돼 **같은 질문 유지**가 됐다. complaint 정의에 "질문 방향 제안"이 없고, 잘못된 질문 방향을 막는 장치가 없다.
  3. **답이 아닌 말은 다음 턴 맥락(HOT MEMORY)에 전혀 안 들어간다.** 그래서 대표가 바로 전에 한 요청을 다음 LLM 이 모른다.
  4. FAIL-C 는 반복 판정(글자쌍) 2회 탈락이다. 재생성 1회 뒤 실패로 끝났다.
- **강한 가설**
  5. FAIL-A: 목적 「친구」 + 남은 칸 수(remaining) + 우선순위 6(정보) → LLM 이 첫 답의 핵심("이성이든 동성이든 편한")에서 한 걸음이 아니라 "뭘 함께 할지"라는 칸 채우기 질문으로 갔다.
  6. FAIL-C 의 두 후보는 첫 질문 틀 「편한 친구와 ○○을 함께…」의 되풀이였다(3·10 의 맥락 누락 때문).
- **확인 불가**
  - 실제 탈락 후보 문장(원칙상 미기록)
  - ask 턴에서 LLM 의 answer_to_user 원문
  - iPhone 동작

## 13. 최소 구조 수정안 (구현하지 않음 · 새 숫자·새 휴리스틱 없음 · DB 변경 0)

1. **규칙 강제 분류 축소**: `ruleKind` 가운데 meta 의 짧은 물음표 규칙은 서버가 종류를 **강제하지 않게** 한다.
   - 규칙은 LLM 에 힌트로만 주거나 삭제한다. 판정은 LLM 이 직전 질문과 함께 한다.
   - 앱·서버·doit-connect 의 RULES 복사본을 같이 고친다.
2. **HOT MEMORY 에 답이 아닌 턴도 넣는다**: 최근 3턴 = 질문 + 사용자 말 + 종류(answer/meta/ask/complaint).
   - 저장하지 않은 말은 앱이 요청에 실어 보낸다(DB 저장 없음). 서버는 그 말을 사실로 쓰지 않고 "직전 대화 흐름"으로만 쓴다.
3. **질문 방향 수리(Repair First)**:
   - complaint 정의에 "질문 방향을 문제 삼거나 이렇게 물어 달라고 제안"을 넣는다.
   - complaint·meta 뒤에는 문제 된 질문을 "이 방향으로 다시 묻지 않음" 목록으로 같은 대화 안에서 넘긴다(요청에 실음, DB 0).
4. **칸 채우기 신호 제거**: `remaining`(남은 칸 수) 입력을 뺀다. 끝 판정은 서버가 이미 하므로 LLM 에 줄 필요가 없다.
   - 프롬프트의 「활동…」 부정 예시 낱말도 뺀다(약한 가설이므로 1~3보다 뒤).
5. **새 회차 격리**: v16 맥락의 confirmed·unconfirmed 는 회차 시작 이후 것만 넣는다(`roundStartOf` 재사용). rejected 는 계속 유지한다(거절은 영구).
6. **FAIL-C 빠져나갈 문**: 반복 탈락이 두 번이면, 실패 대신 다음 두 가지 중 하나로 간다(대표 결정 필요 · 숫자 변경 없음).
   - (a) 탈락 이유 + 이미 물은 질문 목록을 준 두 번째 요청에서 LLM 이 스스로 반복 여부를 판단하게 하고, 서버는 **완전히 같은 문장만** 막는다.
   - (b) 지금 방식(실패 표시)을 유지한다.

## 14. 회귀 위험

- 1: 「활동?갑자기?」 같은 진짜 되물음을 LLM 이 답으로 저장할 위험(FAIL #2 재발). 프롬프트에 "AI 질문에 되묻거나 당황한 반응은 answer 가 아니다"가 이미 있으나 실AI 확인이 필요하다.
- 2: 앱이 보낸 대화 흐름은 사용자 입력이다. 길이 상한·저장 금지 입력 차단을 그대로 적용해야 한다.
- 5: 옛 회차에서 맞다고 한 말이 새 대화 질문에 안 쓰인다. 소개 초안·통합 카드는 영향 없게 v16 질문 맥락만 바꾼다.
- 6(a): 비슷한 질문 반복이 늘 수 있다.

## 대표용 세 문장

1. **활동**: 코드에 박힌 고정 문장이 아닙니다. AI가 「친구를 만나고 싶어요」와 "남은 질문 칸 수"를 보고 "친구와 뭘 할지"라는 칸 채우기 질문을 스스로 만든 것입니다. 대표님 말의 핵심(이성이든 동성이든 편한 사람)에서 한 걸음 나아가지 못했습니다.
2. **취미생활을 또 물은 이유**: 서버 규칙이 짧은 「취미생활?」을 "질문 뜻을 모르겠다"로 강제로 판정했습니다. 이어서 「어떤 취미가 있냐고 물어봐야지」는 "AI에게 한 질문"으로 분류돼 같은 질문을 그대로 두었습니다. 게다가 저장하지 않은 두 말은 다음 턴의 AI에게 전달되지도 않습니다.
3. **마지막 질문을 못 만든 이유**: 대표님이 원한 방향을 모르는 AI가 첫 질문과 거의 같은 질문을 두 번 만들었고, 서버의 반복 검사가 두 번 모두 막아 거기서 멈췄습니다.
