# 엉망 입력 스트레스 검사 보고 (2026-09-17)

## 왜 했나
실기기에서 나온 결함 3개가 전부 "제가 상상한 예쁜 답변"만 검사했기 때문에 새어 나갔다.
그래서 **실사용자처럼 엉망인 입력**을 대량으로 밀어넣는 검사를 새로 만들었다.

## 무엇을 넣었나
- 입력 60가지(실기기·운영 DB에서 나온 실제 문장 포함): `돈때문에`, `밀린돈들때뭄에`, `ㅇㅇ`, `몰라`,
  `모르겠어요`, `ㅠㅠ`, `123`, `ok`, 되묻기(`어떻게 해야 좋을까?`), ECHO 자체 질문(`AI도 오타가 날 수 있어?`),
  지적(`아까 내 질문에는 답하지 않았어`), 정정(`그 뜻이 아니라 쉬고 싶다는 뜻이야`), 긴 문장, 이모지, 영어.
- **일부러 나쁘게 구는 모델**: 모든 후보를 반말로, 같은 뜻으로 반복해서, 답은 회피 문장으로 낸다.

## 이 검사가 실제로 찾아낸 서버 결함 2개 (고쳤다)
1. **되물으면 대화가 죽었다.** 사용자가 되물었을 때 답 후보가 3번 다 품질 검사에 걸리면
   화면이 "질문을 만들지 못했어요"로 끝났다. 이제 고정 회피 문장을 지어내지 않고,
   검사를 통과한 질문으로 대화를 잇는다. 실패 사실은 `asked_reply_failed` 로그로 남긴다.
2. **답이 반말이면 질문까지 같이 죽었다.** 제가 넣은 반말 검사가 답과 질문을 묶어서 보는 바람에,
   답만 반말이어도 후보 전체가 버려졌다. 이제 질문·공감 문장의 반말만 차단하고,
   답의 반말은 '답 품질 실패'로 따로 다뤄 질문은 살린다.

## 아직 확정하지 못한 것 (숨기지 않고 남김)
깊은 여정 검사(STEP 3~7까지, 40회)에서 **거절·정정 뒤에 후보가 전부 막히는 경우**가 보인다.
다만 오늘 이미 두 번, 실패의 원인이 제품이 아니라 **제 검사 장치**였다.
(가짜 모델이 사용자 말 대신 ECHO 자기 문장을 인용하고 있었다.)
지금 가짜 모델은 매번 같은 표현만 인용하도록 되어 있어, 진짜 모델이라면 빠져나갈 수 있다.
그래서 **제품 결함이라고 단정하지 않는다.** 검사에는 `[미확정]` 항목으로 남겨 두었고,
통과로 세지 않는다(node:test todo). 실계정 실행으로 확인해야 한다.
