# 얼굴·지문 로그인 + 「처음부터 다시」 잘 보이게 (2026-09-24)

근거: 대표 "처음부터 시작하기 있다 근데 못 찾겠어 조금 눈에 띌 수 있게 만들고 얼굴로그인 진행해".

**아직 아무도 진짜 휴대폰으로 써 보지 않았습니다.** 아래 검사는 가짜 로그인 서버 + 브라우저의 가상 얼굴 인식 장치 기준입니다.

## 1. 「처음부터 다시」
작은 회색 글씨였던 버튼을 **테두리 있는 동그란 버튼 + ↺ 그림**으로 바꿨습니다(대화 화면 위·아래, 앱 홈).

## 2. 얼굴·지문 로그인 (패스키)
- **로그인 화면**: 「얼굴·지문으로 로그인」 버튼. 이 휴대폰에 등록해 둔 사람만 됩니다. 처음이면 이메일·Google 로 로그인한 뒤 등록합니다.
- **설정(오른쪽 위 톱니바퀴) → 얼굴·지문 로그인**: 「지금 이 휴대폰 등록하기」 · 등록한 기기 목록 · 지우기(한 번 더 묻기).
- 아이폰 = Face ID, 갤럭시 = 지문이나 화면 잠금(얼굴은 기종에 따라 다름, **검증 필요**).
- 얼굴·지문 정보는 휴대폰 밖으로 나가지 않습니다. DO IT 도 Supabase 도 받지 않습니다.
- 카카오톡 같은 앱 안 브라우저에서는 버튼 대신 "사파리나 크롬에서 열어 주세요" 안내.
- **빠져나갈 문**: 얼굴 로그인이 꺼져 있거나 등록이 없거나 취소해도, 이메일·Google 로그인은 그대로 있습니다.

## 3. 바꾼 부품
로그인 부품 `@supabase/supabase-js` 2.57.4 → **2.117.1**(얼굴 로그인이 들어간 판). 다른 부품은 판이 그대로입니다(설치 목록 대조).
- 영향: 첫 화면 파일이 압축 기준 **138KB → 173KB**(약 35KB 증가). 보통 휴대폰 인터넷에서 0.1초 안팎.
- **내 실수와 정리**: 작업 폴더의 설치 목록(package-lock.json)이 원래 다른 폴더 주소(`../../implementation/project/…`)로 적힌 불완전한 파일이었습니다. 부품을 바꾸다 이 때문에 검사 도구가 빠졌고, 한때 검사 26개가 깨졌습니다. 목록의 판 번호는 그대로 두고 주소만 이 폴더 기준으로 바로잡아 다시 설치했습니다(바뀐 판 0개, 쓰지 않는 3개 제거). 이제 목록에 다른 폴더 주소가 섞이지 않았는지 검사가 확인합니다.
